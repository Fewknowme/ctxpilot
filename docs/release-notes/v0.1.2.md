# ctxpilot v0.1.2

Released May 20, 2026.

## Highlights

- Added a free local AI provider powered by Ollama.
- `ctx init` now guides new projects through either local Ollama setup or BYO Anthropic/OpenAI keys.
- Local provider configuration is stored in `.ctxpilot/config.json` and can also be set with `CK_PROVIDER=local`, `CK_MODEL`, and optional `CK_LOCAL_URL`.
- `ctx build` and `ctx update` now reuse the configured model for the active provider, including locally selected Ollama models.
- Signal extraction is more resilient for local models: ctxpilot repairs common near-JSON output, retries strict JSON generation, and archives parse-failure payloads instead of failing the full update.

## New Local Provider

You can now run ctxpilot without sending project context to hosted model providers:

```bash
brew install ollama
ollama pull gemma3:4b
ctx init
```

Choose `Free (local)` during initialization, then select one of the Ollama models already pulled on your machine.

Manual configuration is also supported:

```env
CK_PROVIDER=local
CK_MODEL=gemma3:4b
CK_LOCAL_URL=http://localhost:11434
```

## Reliability Improvements

- Local/OpenAI-compatible requests now resolve models through the correct provider path, so missing local model configuration fails early with a helpful message.
- Extraction retries now preserve the previous graceful fallback behavior when the retry call fails.
- JSON repair is string-aware, so URLs such as `https://example.com` are not corrupted while stripping model-generated comments.
- Added regression tests for Ollama detection, local model resolution, and signal extraction fallback behavior.
